# Session worklog (status dot, touched files, transcript viewer)

**Location:** `src-tauri/src/sessions.rs` (touched-files + transcript sections), `src/panels/LeftSidebar/LeftSidebar.tsx` (status dot), `src/panels/Editor/SessionPanel.tsx`, `src/panels/Editor/TranscriptViewer.tsx`, `src/panels/Editor/Editor.tsx` (Session right-panel mode + transcript virtual tab), `src/components/Toolbar/Toolbar.tsx` (stat row), `src/utils/touchedFiles.ts`, `src/utils/editingNow.ts` (in-editor markers)

> **The transcript viewer was removed 2026-07-31** (branch `navigation`, phase 7,
> commit 022d6b6). It predated the chat panel; both rendered the same turns from
> the same parser, and only one of them can approve a tool call. Gone with it: the
> editor's `transcript` tab kind, the `OPEN_TRANSCRIPT` event, both
> `resume_args.length === 0` fallback branches that existed only to emit it, and
> the `session_transcript` command plus its page type. **`parse_transcript_turns`
> stays** - chat replay (`chat_session_detail`), the needs-you tail state and
> title extraction all read it. Read the viewer sections below as history.

A session row shows whether its agent is actually running (a probe-confirmed dot, not just "a tab is open"), and selecting a session reveals what it touched and lets you read its transcript, without the head-only [[component_session_scanner]] ever reading a full file on its own. Three layers, built as one ticket: liveness probing (row dot), touched-file extraction (git join), and a read-only transcript viewer.

## Responsibilities

- **Liveness dot** (`LeftSidebar.tsx`): `session_running(id, agent)` now takes a per-agent `pgrep -f` pattern built by `session_pattern` (`sessions.rs`) — an alternation like `claude (--resume|-r) <id>` or `pi --session .*<id>` — replacing a bare-uuid match that collided with any process whose cmdline happened to contain the id (including a transcript merely opened in `less`). A `probes` cache (session id -> last known running bool) is **trigger-driven only**: it re-probes on row selection, `sessions://changed`, and window refocus (`getCurrentWindow().onFocusChanged`), never on an interval. Solid = a live tab exists AND the probe confirms running; hollow = no tab but the probe confirms running elsewhere (a detached resume); none otherwise.
- **Fresh-tab backfill** (`Terminal.tsx::backfillFreshSessions`): a just-spawned agent tab has no `sessionId` until its transcript file appears. On `sessions://changed`, a tab is backfilled only when it is the *one* unattributed agent tab in its workspace, matching cwd and `SessionMeta.created_at >= tab.spawnedAt`. `created_at` is the file's btime (falling back to mtime); `spawnedAt` must be floored to whole seconds (`Math.floor(Date.now()/1000)`) to compare against the backend's whole-second epoch. The match mutates `tab.sessionId` **in place** then shallow-copies the outer array — see [[gotcha_reordering_a_referentially_keyed_for_must_preserve_object_identity]], which this nearly violated (a `.map`-rebuild would have remounted the tab and killed its live PTY).
- **Touched-files extraction** (`sessions.rs`, `TouchedIndex`): `session_touched_files(path, agent)` reads the **full** transcript once (mtime-cached, separate from the scanner's head-only `SessionIndex`/`PiIndex`), classifying every file-affecting tool call into a `TouchOp` (`Read`/`Create`/`Edit`/`Delete`, serialized lowercase). Dedup rule is **latest write-class touch wins; a later Read never downgrades** a prior Create/Edit/Delete — a file created then re-read must still show as created. Claude tools: `Write`->create, `Edit`/`MultiEdit`/`NotebookEdit`->edit, `Read`->read, `Bash`->best-effort infer (`sed -i`, a trailing `>`/`>>`, `rm` only — anything else is invisible here, git's diff is the backstop). Pi tools are **lowercase** (`write`/`edit`/`read`/`bash`) with `arguments.path` instead of Claude's `input.file_path` — confirmed against real local transcripts, not assumed from prose. `session_detail` shares the same cache for its `touched_count` (writes/creates/deletes only).
- **Compaction count** (`sessions.rs`, `session_detail`): the transcript stat pass also counts how many times a session was compacted, surfaced in the Toolbar stat row (`FoldVertical` glyph + count, plus an `ArrowDown` + reclaimed-tokens when known). The per-line scan was extracted into a **pure** `scan_counts(reader: impl BufRead) -> RawCounts` (every `SessionDetail` field except `touched_count`, which needs the Tauri `State`), so the counts are unit-testable without constructing a command; `session_detail` is now `open file -> scan_counts -> attach touched_count`. Dispatch is by record `type` (Claude and pi strings don't overlap), so no agent hint is passed. **Marker shapes, confirmed on disk:** Claude `{type:"system", subtype:"compact_boundary", compactMetadata:{preTokens, postTokens}}` — counted only when `isSidechain != true` (matching ccstatusline's rule), reclaimed summed as `preTokens - postTokens` (`saturating_sub`) only where both are present; pi `{type:"compaction", tokensBefore}` — no post-token, so it lifts the count but reclaimed stays **0 meaning unknown, never "zero reclaimed"** (the Toolbar omits the reclaimed marker and its tooltip clause when 0); opencode has no compaction concept and reports 0.
- **Session panel** (`SessionPanel.tsx`, a new right-panel mode in `Editor.tsx` shown when a session is selected): the touched list defaults to `op !== "read"` with a reads toggle, grouping any file outside the session's recorded `cwd` (`isUnderPath` vs `Selection.sessionCwd`) under "outside project" — the backend deliberately returns plain absolute paths only, so this bucketing is frontend-computed. Expand-on-click joins with git (`git_diff_text(projectRoot, absolutePath)` — git accepts an absolute pathspec directly, no relativizing needed) in its own path-keyed `Set`, separate from the touched-file array so a `sessions://changed` refetch (which replaces that array wholesale) doesn't need identity preservation. Collision badges count other **live-tab** sessions that also touched a path (via the same `list_sessions` + live-tab-id join [[component_worktree_lifecycle]]'s `countRunningAgents` uses), deliberately bounded — no historical transcript fan-out.
- **Transcript viewer** (`TranscriptViewer.tsx`, opened via the session context menu's "Open transcript"): `session_transcript(path, agent, cursor)` parses the full transcript into a unified `TranscriptTurn{role, ts, blocks}` list (`role`: `"user"`/`"assistant"`/`"tool"`; `block.kind`: `"text"`/`"thinking"`/`"tool_call"`/`"tool_result"`), paginated tail-first (`cursor` is the chronological index of the oldest turn already returned; `None` once the oldest turn is reached). Pi's tool result is a **standalone** top-level `toolResult`-role message (not nested in the next turn like Claude's `tool_result` block), mapped to its own synthetic `"tool"`-role turn. Reuses `extract_text`/`parse_rfc3339_secs` rather than re-deriving either. Re-parses the full file on every call (no cache) — deliberate, since the viewer opens on demand rather than on every session-row render.
- **Editor tab model** (`Editor.tsx`): the center-pane tab array became a discriminated union (`FileTab | TranscriptTab`, keyed by `tabId()` = the file path or `` `transcript:${id}` ``) so a transcript opens as a **virtual tab** alongside real file tabs in the same `OverflowTabBar`. `CodeEditor` stays **mounted at all times** — a transcript tab is a `position:absolute; inset:0` CSS overlay covering it, not a conditional unmount — because `CodeEditor` owns per-buffer `EditorState`/undo history in a component-local map that unmounting would discard.

- **Agent-touched markers in the editor** (`src/utils/touchedFiles.ts`): files the *selected* session wrote get a subtle tint plus a dot in the FileTree and a dot on matching open editor tabs. **Reads are excluded** — `session_touched_files` reports them, but an agent reads far more than it writes, so tinting reads would light up most of the tree and stop meaning anything; `writtenPaths` keeps create/edit/delete only. **Dirs are never marked**: a dir tint would have to mean "something below me changed", a different claim than the row makes. The set is a module-level signal, not a prop, because `FileTree` marks rows inside recursive `TreeNode` (same precedent as `liveStatuses`); `Editor` is the sole writer. Refreshed on `sessions://changed`, cleared **before** the fetch on selection change so a previous session's markers never linger mid-flight, with the usual latest-request-wins guard.
- **Live "editing now" indicator** (`src/utils/editingNow.ts`): while the selected session is Executing, the file it is writing *right now* pulses on its tree row and tab, and the Session panel shows ``editing `foo.ts` ``. Two signals of different strength feed it and the weaker one degrades rather than lies — see [[concept_evidence_tiered_attribution]] for the full model. `session_editing_now` is a **reuse, not a new parser**: `latest_written()` (max `last_ts` among non-read) over the existing mtime-cached `touched_files_cached`, so it inherits every adapter's parser and the cache for free, and polling during a turn costs a full parse only when the transcript actually grew.

## Connections

- Extends [[component_session_scanner]] — same file (`sessions.rs`), same on-disk sources, but a deliberately separate cache (`TouchedIndex`) so the scanner's head-only cheapness is untouched; the scanner's `list_sessions` is reused (not duplicated) for the collision-badge join.
- Hosted inside [[component_cm6_editor]] — the Session mode is a fourth right-panel `<Match>`, the transcript viewer a virtual center-pane tab.
- Feeds on [[component_worktree_lifecycle]]'s live-tab surface (`LiveTab[]`) for both the status dot and collision badges.
- Governed by [[adr_stack_choice]] — filesystem-as-source-of-truth extends to touched files and transcript turns, not just session metadata.
