# jsdom measures everything as zero-wide, so OverflowTabBar hides every tab label

Don't anchor a component test on an editor or terminal tab's label. Why: `OverflowTabBar` decides what fits from `getBoundingClientRect`, jsdom returns zeros for all of it, so the entire strip folds into the `+N` menu and not one tab name is in the DOM to query - a test that mounts a pane and waits for `getByText("a.ts")` times out against perfectly good code. Assert on something layout-independent instead: the pane's own empty state answers "is anything open", and a command's effect (which file it staged, which prompt it raised) answers the rest. Stubbing `ResizeObserver` is still needed so the bar can mount, but it does not fix this - the measurement is a separate call.

**A role query cannot reach those tabs either, and that is worse than it sounds.** The tabs are not absent from the DOM: the bar renders an inert `aria-hidden` *ghost* copy of the whole strip to measure widths from, so with every width zero the ghost is the only copy of most tabs in the document. `getByTitle` never cared, which is why swapping a `title` for an accessible name broke a run of Editor tests that had looked layout-independent. `screen.getAllByRole("tab", { name, hidden: true })[0]` is the way through - the ghost is the same `renderTab` output, handlers and all, so clicking it exercises the real control. Wrapped as `tab()`/`tabs()` in `src/test/tabs.ts`.

**The cause above is wrong, and the correction matters.** It is not the zero widths. The bar seeds its visible count from `props.items.length` at mount, when the list is still empty, and only corrects it in an `onMount` `requestAnimationFrame` that jsdom never runs, so every tab overflows before a single width is read. `installAnimationFrame()` in `src/panels/Editor/__fixtures__/editorHarness.ts` runs that callback synchronously: widths stay zero, and one real tab appears in the visible row. Use it, plus `visibleTab(name)` from `src/test/tabs.ts`, for anything that must reach the **real** control rather than the ghost, which since #103 is anything involving a menu: the ghost carries no menu trigger, so a right-click there asks a copy with nothing to answer with. See [[lesson_the_measuring_ghost_answered_the_test]].
**This is solved now, and `visibleTab()` is gone.** `src/test/tabLayout.ts` gives the bar a real layout under jsdom - `getBoundingClientRect`, `offsetWidth` and `clientWidth` answered for elements in an `.otab-ghost` strip and the element holding it, everything else delegated. **Scoped to the bar deliberately**: a blanket layout changes what CodeMirror, the dialogs and the slider measure. The default bar is 4000px so nothing overflows unless a test says `setTabBarWidth(px)`, which is what made moving the call sites mechanical. `tab()`/`tabs()`/`closeOf()` in `src/test/tabs.ts` now read the row a browser would draw, and `installAnimationFrame()` moved to `src/test/frames.ts` so the terminal can reach it too - it lived in the editor harness, which is why no terminal test had ever reached a tab. Since #111 the ghost is inert, so it is no longer a second live copy to be reached by accident.
