# Safe-send: the routed insert-only write path

The single write path every composed message (a hunk comment, an editor-selection mention, an "ask agent to draft" request, an LSP diagnostic) uses to land text at a session's prompt. It never submits on the user's behalf — the text sits at the prompt, unsubmitted, until the user presses Enter themselves.

## How it works

- **One entry point, `requestSend`** (`src/utils/safeSend.ts`). Any panel builds a `SessionTarget` (the routing/resume subset of `SendToSession`: `sessionId`, `agent`, `folderPath`, `sessionCwd`, `sessionPath`, etc.) and calls `requestSend({ ...target, text })`. This fires a `SEND_TO_SESSION` event carrying a fresh `requestId`; `Terminal.tsx` is the **sole** consumer (it alone owns `pty_write` and tab/session state) and answers with `SEND_TO_SESSION_RESULT` matched by that id. `requestSend` resolves to a `SendResult`: `"sent" | "blocked" | "timeout"`.
- **Insert-only, never auto-submit.** `sanitizeForSend` collapses the composed text to one line (a raw multi-line PTY write would submit intermediate lines). `bracketedPaste` wraps it (`\x1b[200~...\x1b[201~`) with **no trailing Enter**, so it lands in the agent's input buffer for the user to review.
- **The sanitizer also strips control bytes**, mapping tab to space and removing the rest of C0/C1 (`\p{Cc}`). A payload carrying the paste terminator would end the framing early and hand the terminal everything after it as typing. This mattered only once a composer carried text the user did not write, which is the fifth one; see [[lesson_sanitize_text_you_did_not_author]].
- **Probe-gated, re-checked at flush time.** `sendWithProbeGate` probes readiness (`session_running`, plus `session_tail_state` when a transcript path is known) **immediately before every write**, direct or queued — not just once at call time. A resumed-but-booting session queues (polling every `QUEUE_POLL_MS` up to `QUEUE_TIMEOUT_MS`); a session mid-permission-prompt ("blocked") is refused instantly rather than waiting out the timeout, since queuing behind a stuck prompt would never resolve.
- **Never lands in a bare shell.** Because every terminal tab is a login shell first ([[concept_shell_hosted_tabs]]), a `pty_write` immediately after focus-or-resume would type into the *shell*, not the agent (no OSC 133 ready signal exists). The probe-gate is what prevents this — a queued send only flushes once the agent itself is confirmed live.
- **Composers are pure and additive.** `composeHunkComment` (`In @<file> lines X-Y: ...`), `composeSelectionMention` (`@<file>#L<start>-L<end>`), and `composeDiagnostic` (`@<file>#L<start>-L<end> <severity>: <message>`) all share one relativity rule via `mentionPath`: relative inside the target's cwd, absolute outside it. `composeDiagnostic` additionally flattens multi-line server messages — TypeScript emits plenty, and a raw newline would submit the prompt on some agents, breaking the very contract this module exists to keep.
- **A `.pdf` is spelled out by page, not by line.** `composeSelectionMention` answers `@manual.pdf (page 3)` or `@manual.pdf (pages 3-4)` for a PDF path, and `chipLabel` follows with `@manual.pdf p.3`. Inside Sway a PDF's "line" *is* its page, because the chips, `OPEN_IN_EDITOR` and the jump list already speak in lines and a second event shape would have to be invented otherwise; to the agent it is not, because it opens the file with a PDF reader and would read `#L3` as a third line of text. The predicate is `isPdfPath` in `src/utils/pathScope.ts`, shared by the viewer and both composers.
- **The Rust half renders that from one function.** `turn_frame` (`chat/claude_transport.rs`) and `prompt_blocks` (`chat/acp.rs`) each carried their own copy of the `@path#L{s}-{e}` match; both now call `model::file_ref_locator`, which is also where the `.pdf` branch lives. Two copies of a wire format are two chances to tell the agent two different things about one selection. `history.rs`'s `split_range` reads a rendered ref back, but only for a *labelled* one, and no label carries a range, so the page form never reaches it.
- **Never discards typed text.** A caller (e.g. `HunkCommentInput`) keeps the user's typed comment in its own input on anything but `"sent"`, so a timeout or a blocked refusal is retryable without retyping.
- **A fourth composer, `composeConflictAsk`** (`src/utils/conflictAsk.ts`), hands a merge conflict to the agent from the same three index stages the three-way view is built from ([[concept_three_way_conflict_model]]). Two surfaces offer it, the banner over a conflicted buffer and the Conflicts row, and a single composer plus a single send path is what keeps their wording identical by construction; the byte-for-byte equality of the two payloads is asserted in the one mount that renders both.
- **It reads the stages at send time rather than taking them as an argument.** That is what lets a panel row ask about a file it has never opened, and it doubles as the staleness guard for free: `git_conflict_stages` refuses a path that is no longer unmerged, so a panel left open across a terminal-side `git merge --abort` toasts git's own words instead of asking an agent to resolve a merge that ended.
- **A fifth composer, `composeThreadAsk`** (`src/utils/threadAsk.ts`), hands a pull request review comment to the session that wrote the branch, quoting the opening comment and up to `REPLY_CAP` replies and naming the line range the thread is anchored to. It is the first composer whose text has an author outside this machine, which is what forced the control-byte guard above. Its outcomes (blocked, timeout, no owning session) are reported **on the thread card**, not as toasts, because a toast cannot say which thread failed once a stack has scrolled.
- **A sixth composer, `composeFrame`** (`src/utils/debugAsk.ts:85`), hands a paused debug frame to the agent: which session stopped and why, where, the way in, and what is in scope there. Two surfaces offer it, the selected stack row and the variables heading, and `frameAsk` reads `currentFrame()` and the scope stores *itself* rather than taking them as arguments, so both compose the identical text by construction (the same rule `composeConflictAsk` established).
- **It is the first composer whose input is unbounded in size as well as in authorship.** A scope can hold five thousand names and a value can be a serialized object, so every borrowed string is clipped (`TEXT_CAP` 60) and every list is capped (8 frames, 3 scopes, 20 names), with what was left out **stated** rather than silently dropped. Frame *names* are clipped too: js-debug names a frame `function Module(id = '', parent) {.executeUserEntryPoint`, so a name is arbitrary program text and a cap that covers only values is not a cap.
- **The capability gate is one module, not one per surface.** `sendTargetFor` / `sendBlockedReason` (`src/utils/sendTarget.ts`) answer with the target *or* the reason ("Select a session first", "This agent's sessions can't be resumed"), so a caller cannot build a `SessionTarget` without having passed the gate. It replaced a third hand-written copy of the same two checks and the same two sentences across the Problems, TODO and Debug panels.
- **Only the timeout is reported by the caller.** `Terminal.tsx` already toasts a blocked target with the shared wording, so a composer that also toasted it would say it twice; the timeout is the one case where no Terminal answered at all.

## Why it's this way

Auto-submitting agent commands from a UI action is a much larger trust boundary than inserting text for a human to review — the plan (`review-to-prompt + commit flow`) deliberately scoped every composed-write surface (hunk comments, selection mentions, the commit-draft request) to insert-only, with auto-submit left as a possible future *explicit* per-action opt-in, never a default. The probe-gate-at-flush-time design specifically defends against the shell-vs-agent race: a session can transition from "just resumed, hosting a bare shell" to "agent running" between when a comment is queued and when it would otherwise fire, so the check has to happen at write time, not enqueue time.
